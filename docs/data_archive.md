## 2. Proposed Archival Tranches (Zenodo / Open Science Framework)

To ensure long-term reproducibility while keeping the Git repository lightweight for cloning and CI execution (target size < 300 MB):

### Tranche A: Git Repository (Retained In Tree, Target Size: ~250 MB)
- Package code (`sentinel/`), unit tests (`tests/`), reproducibility scripts (`scripts/`).
- Dataset manifest (`datasets/synthetic-expanded-v1/manifest.json`).
- All aggregated publication tables, LaTeX sources, SVG figures, and statistical summaries (`results/tables_20seed/`, `results/figures_20seed/`, `results/matched_fpr_v2/`, `results/novelty/publication_scale_v3_report/`).
- `scripts/reproduce_all.py` regenerates all paper tables and figures strictly from these retained summaries in ~20 seconds without requiring external raw event logs.

### Tranche B: Zenodo Open Data Deposit (Target Size: ~9.2 GB)
- Full uncompressed JSON-RPC event logs:
  - `results/novelty/publication_scale_v3/` (~6.33 GB)
  - `results/novelty/publication_scale_v2/` (~1.56 GB)
  - `results/novelty/publication_scale_complete/` (~1.12 GB)
  - `results/novelty/publication-scale-20261016/` (~62 MB)
- To be assigned a persistent DOI upon external deposit (e.g. `[PENDING DEPOSIT - PLACEHOLDER: 10.5281/zenodo.PENDING]`); cited in `README.md` and the paper's *Data and Code Availability Statement* only after real deposit is completed.

## 3. Human Confirmation Required Prior to Deletion / History Rewrite

**Rule 7 Compliance**: No file moves, deletions, or history rewrites will be executed without explicit authorization. The repository maintainers must approve the following checklist before camera-ready submission:
1. Verify Zenodo deposit tarball hash against local files.
2. Confirm that `python scripts/reproduce_all.py` passes with archived traces downloaded or cached.
3. Review and approve the git history rewrite or archival script before executing.
